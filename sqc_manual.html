💡 Before we start — what is "code"?

Code is simply instructions written in a language a computer understands. Just like you can write instructions in English ("turn left, go straight, stop"), you write instructions for a browser in HTML, CSS and JavaScript. The browser reads those instructions and turns them into the beautiful page you see on screen.

📄 HTML

What is HTML?

HTML (HyperText Markup Language) is the skeleton of a webpage. It describes what content exists and how it's organised — headings, paragraphs, buttons, images. Think of it like the bones of a body.

Basic HTML structure 
<!-- This is a comment — the browser ignores it -->

<div class="my-box">         <!-- A container (div = division) -->
  <h1>Hello Sisters!</h1>    <!-- A big heading -->
  <p>Welcome to SQC.</p>     <!-- A paragraph -->
  <button>Click me</button>   <!-- A clickable button -->
</div>

🏷️ Tags always come in pairs

Every HTML element has an opening tag <h1> and a closing tag </h1> (notice the slash). Everything between them is the content. The only exception is self-closing tags like <img> and <br>.

▼ Deep Dive: HTML in the SQC website ▼

In your index.html file, the structure looks like this:

  • <head> — invisible settings: the page title, fonts, colours, scripts to load
  • <nav> — the top navigation bar with Home, Resources, Bloom etc.
  • <div class="page" id="page-home"> — each page section is a div with a unique id
  • <div class="signin-modal"> — the sign-in popup that floats over the page
  • <footer> — the bottom section with links and email
  • <script> — where all the JavaScript lives (at the very bottom)

Only one page div is visible at a time — JavaScript hides and shows them when you click the nav links.

🎨 CSS

What is CSS?

CSS (Cascading Style Sheets) is the styling of a webpage. If HTML is the skeleton, CSS is the skin, clothes and makeup. It controls colours, fonts, sizes, spacing, animations — everything visual.

How CSS works 
/* Select something by its class name, then describe how it looks */

.nav-link {
  background: white;         /* background colour */
  color: #c4748a;            /* text colour (rose pink) */
  font-size: 13px;           /* how big the text is */
  border-radius: 20px;       /* rounded corners */
  padding: 7px 16px;         /* space inside (top/bottom left/right) */
  cursor: pointer;           /* show a hand when hovering */
}

🎯 The dot means "class"

When you see .nav-link in CSS, the dot means "find all HTML elements that have class="nav-link" on them and apply these styles". You can reuse the same class on many elements.

⚡ JavaScript

What is JavaScript?

JavaScript (JS) is the brain of a webpage. HTML is the structure, CSS is the appearance — JavaScript is what makes things happen. When you click a nav link and a new page appears, that's JavaScript. When your garden loads from Google Sheets, that's JavaScript.

JavaScript example — the showPage function 
// This function runs every time you click a nav link
function showPage(name) {

  // 1. Hide ALL pages
  document.querySelectorAll('.page')
    .forEach(p => p.classList.remove('active'));

  // 2. Show ONLY the page we want
  document.getElementById('page-' + name)
    .classList.add('active');

  // 3. If going to bloom page, load the flower data
  if (name === 'bloom') loadBloom();

  // 4. Scroll back to the top
  window.scrollTo(0, 0);
}

💡 Functions are recipes

Think of a JavaScript function like a recipe. You write the recipe once (function showPage(...)) and then you can "cook" it as many times as you like by calling it (showPage('home')). The bit in the brackets is the ingredient — in this case, which page name to show.

▼ Deep Dive: async/await — fetching data from Google Sheets ▼

You'll see async and await a lot in your code. These are used when JavaScript needs to wait for something — like waiting for Google Sheets to send back data.

Imagine sending a letter and waiting for a reply. async means "this function will need to wait at some point". await means "wait right here for the reply before continuing".

The try { ... } catch(err) { ... } pattern means "try this, but if something goes wrong, catch the error and do this instead" — like having a backup plan.

📑 HTML Structure

The Pages

The SQC website is a single-page app — meaning it's actually all one HTML file, but only one section is visible at a time. Each "page" is a <div class="page"> with a unique ID.

🔐 JavaScript

Google Sign-In

The sign-in system uses Google Identity Services — Google handles all the security. You never store passwords. Here's how it works:

🔄 The sign-in flow

  • Sister clicks the Google button → Google verifies her identity
  • Google sends back a token (an encoded piece of data proving who she is)
  • Your code decodes the token to get her name, email and profile picture
  • If it's her first visit, she picks her SQC name from the list
  • Everything is saved to localStorage — a storage space in the browser that remembers things even after you close the tab
How the token is decoded 
// Google sends a "credential" (a long string of text)
// We split it into 3 parts, take the middle one, and decode it
const payload = JSON.parse(
  atob(response.credential.split('.')[1])
);

// Now payload contains:
payload.name     // "Tazmina"
payload.email    // "taz@gmail.com"
payload.picture  // URL of her Google profile photo

🌸 JavaScript + SVG

The Bloom Page

The collective bloom tracker is one of the most creative parts of the site. It uses SVG (Scalable Vector Graphics) to draw the flower — a special HTML-like language for drawing shapes in the browser.

🌸 How petals are drawn

Each petal is an ellipse (a stretched circle). The code positions them evenly around a centre point, like clock hands. For 9 sisters, each petal is rotated by 40° from the previous one (360° ÷ 9 = 40°).

How a single petal is drawn 
// For each sister, calculate her petal's angle
const angle = (i / totalSisters) * 2 * Math.PI;

// If she completed Morning Adhkar — fill with colour
if (isDone) {
  petal.setAttribute('fill', '#c4748a');   // solid pink
  petal.setAttribute('opacity', '0.92');
}
// If not completed — show outline only
else {
  petal.setAttribute('fill', 'none');        // empty
  petal.setAttribute('stroke-dasharray', '4,3'); // dashed border
}

🌿 Garden Tracker

The Garden Tracker

The Ibadah Garden Tracker lives in a separate GitHub repo (tazcodez/sqcgardens) and is embedded inside the SQC website as an iframe — like a picture-in-picture TV. It has its own HTML, CSS and JS but connects to the same Google Sheet.

📅 What "weekly" means

The tracker shows only entries from Monday to Sunday of the current week. The Apps Script calculates the start of the week automatically using JavaScript's date functions. At midnight on Monday, every garden resets — no data is deleted, it just shows a fresh week.

🌱 How plants grow

When a sister logs ibadah, she picks a plant/flower. That plant name is saved to the Google Sheet. When the tracker loads her garden, it reads all her plant names from that week and displays the matching image from the plants/ folder. The image filename must exactly match the plant name.

▼ Deep Dive: How the plant emoji lookup works ▼

There's a big object called PLANT_EMOJI in the tracker code — it's like a dictionary that says "if the plant name contains this word, use this emoji". For example:

'roses': '🌹',
'sunflower': '🌻',
'bamboo': '🎋'

The code checks if the plant name contains the key word — so "Red Roses" would match 'roses' and get the 🌹 emoji. If no match is found, it defaults to 🌿.

⚙️ Google Apps Script

What is Google Apps Script?

Google Apps Script (GAS) is a free tool built into Google Sheets. It lets you write JavaScript code that reads and writes data in your sheet. When deployed as a Web App, it becomes a mini API — a URL that websites can call to get or send data.

🌐 What is an API?

API stands for Application Programming Interface. Think of it like a restaurant menu — your website is the customer, the Apps Script is the waiter, and the Google Sheet is the kitchen. The customer tells the waiter what they want (an "action"), the waiter goes to the kitchen (the sheet), gets the data, and brings it back.

📡 Apps Script

The Actions

Your Apps Script handles 7 different "actions" — each triggered by adding ?action=something to the URL. Here's what each one does:

📋 members — Get all member names

  • Called by: Garden tracker on load, Sign-in name picker, Bloom page
  • Reads from: The Members sheet, column A
  • Returns: A sorted list of names e.g. {"names":["Aisha","Fatima","Nahya"]}
  • To add a sister: Simply add her name to the Members sheet — no code changes needed!

➕ addMember — Add a new sister

  • Called by: The sign-in name picker when someone types a new name
  • Writes to: The Members sheet
  • Checks for duplicates: Won't add the same name twice

🌸 todayAdhkar — Get today's bloom data

  • Called by: The Bloom page when it loads
  • Reads from: Form Responses 1, filtering for today's Morning Adhkar entries
  • Returns: All member names + whether each has completed Morning Adhkar today
  • Resets: Automatically at midnight since "today" changes

📝 log — Submit ibadah entry

  • Called by: The Log Ibadah form when a sister submits
  • Writes to: Form Responses 1 — appends a new row
  • Columns written: Timestamp, Name, Pages, Seedling, WhiteFlower, RedFlower, YellowFlower, PurpleFlower, Day, IbadahType, Morning Adhkar checklist, Morning flower, Evening Adhkar checklist, Evening flower, Hifz ayats, Hifz plant, (4 empty), Tahajjud flower

🌿 (default) — Read weekly garden

  • Called when: No action is specified — just ?name=Aisha
  • Reads from: Form Responses 1, filtering for this week's entries for that name
  • Returns: All of that sister's ibadah entries for Mon–Sun of the current week
⚠️ Every time you change the Apps Script, you must go to Deploy → Manage Deployments → Edit → New Version → Deploy. Otherwise the live website still uses the old version!
🚀 Apps Script

Deploying the Apps Script

Deploying means "publishing" your Apps Script so the website can call it. Think of it like publishing a book — you can edit the manuscript all you like, but nobody can read it until you publish a new edition.

📝 The deployment checklist

  • ✅ Make your changes in the Apps Script editor
  • ✅ Press Ctrl+S to save
  • ✅ Click Deploy → Manage Deployments
  • ✅ Click the pencil ✏️ icon on your existing deployment
  • ✅ Change version to "New version"
  • ✅ Click Deploy
  • ✅ The URL stays the same — no need to update the websites

🔧 Change the bloom flower for a specific day

Find the const FLOWERS = [...] array and the const map = [6,0,1,2,3,4,5] line. The map says which flower index (0–6) is used for each day (Sun, Mon, Tue, Wed, Thu, Fri, Sat). Change the numbers to swap flowers between days.

🔧 Update the service worker after site changes

Every time you update the website, open OneSignalSDKWorker.js and bump the cache version number:

❌ BEFORE

✅ AFTER
const CACHE_NAME = 'sqc-cache-v3';

This forces everyone's browser to download the fresh version instead of showing the cached old one.
